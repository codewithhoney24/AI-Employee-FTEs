
# K-Electric AI Employee - System Architecture (V3)

This document outlines the end-to-end architecture of the K-Electric AI Employee system, a hybrid autonomous agent designed for business operations, CRM management, and social media automation.

## 1. Architectural Philosophy
The system is built on a **"State Machine via File System"** paradigm, combining autonomous background processing with strict **Human-In-The-Loop (HITL)** governance for critical actions.

*   **Autonomy:** Background watchers monitor data and execute routine workflows without human intervention.
*   **Security (HITL):** Financial transactions, final social posts, and critical communications are gated behind a WhatsApp approval mechanism.
*   **Decentralization:** The system uses distinct micro-services (Python Engine, Node.js Gateway, MCP Servers) communicating via Webhooks and shared storage.

---

## 2. Core System Components

### A. The State Machine & Memory (Obsidian Vault: `KE_AI_Vault`)
Instead of a traditional SQL database, the system uses a Markdown-based Obsidian Vault. This allows both the AI and Humans to read, edit, and understand the system state natively.
*   **`Needs_Action/`**: Ingestion point for raw leads, incoming messages, or un-processed data.
*   **`Pending_Approval/`**: Holding area for drafts (social posts, invoices) awaiting human consent.
*   **`Approved/` & `Done/`**: Execution triggers and archival folders.
*   **`Dashboard.md`**: Live-updating KPIs and business metrics generated by the AI.

### B. The AI Brain (Python Engine: `api_employee_v2/ai_engine`)
The central reasoning layer, powered by the Google GenAI SDK (`gemini-3.1-pro-preview`).
*   **`app.py`**: The main Flask server that receives webhooks from WhatsApp and orchestrates decisions.
*   **`fte_watcher.py` & `ralph_loop.py`**: Background daemons that run 24/7. They watch the Obsidian Vault for new files, parse the Markdown, and trigger the AI to make decisions or execute skills based on the folder state.

### C. The Human-In-The-Loop Gateway (Node.js: `whatsapp_gateway`)
A dedicated Node.js service using `@whiskeysockets/baileys` to maintain a persistent connection with WhatsApp Web.
*   **Function:** Acts as the primary interface for the human admin. 
*   **Workflow:** The Python engine sends drafted content to this gateway via HTTP. The gateway sends a WhatsApp message to the admin. When the admin replies (e.g., "YES"), the gateway fires a webhook back to the Python engine to authorize the action.
*   **Security:** Enforces phone number verification to ensure only authorized administrators can trigger approvals.

### D. The Execution Layer (Skills & Tools)
A modular Python architecture (`backend/skills` & `executor/`) that provides the AI with "hands" to interact with the outside world.
*   **`odoo_skill.py`**: Uses XML-RPC/REST to map AI decisions into actual Odoo ERP entries (Leads, Invoices, CRM).
*   **`email_skill.py`**: Handles automated email responses and portfolio dispatching.
*   **`social_skill.py` & `twitter_skill.py`**: Connects to the Twitter API v2 (`tweepy`) and Meta Graph APIs for publishing approved content.

### E. The Application Layer (Frontend & Backend APIs)
*   **FastAPI (`backend/main.py`)**: Exposes REST endpoints for the dashboard and external integrations.
*   **Next.js Dashboard (`frontend/`)**: A modern web interface offering a high-level view of the AI's operations, overriding the basic Obsidian dashboard for executive presentations.

## 3. End-to-End Workflow Examples

### Scenario 1: Autonomous CRM Sync (No Human Needed)
1.  **Ingestion:** A web form submits a lead. A markdown file is dropped into `Needs_Action/`.
2.  **Detection:** `fte_watcher.py` detects the new file and passes the context to the GenAI engine.
3.  **Reasoning:** AI analyzes the lead, extracts entities (Name, Value, Intent), and updates the Markdown frontmatter (Priority: High).
4.  **Execution:** AI triggers `odoo_skill.py`, which pushes the data into Odoo CRM. The file is moved to `Done/`.

### Scenario 2: Social Media Post with HITL Governance
1.  **Drafting:** The AI engine identifies a trending topic and drafts a tweet, saving it in `Pending_Approval/`.
2.  **Notification:** The Python engine sends the draft to the Node.js WhatsApp Gateway.
3.  **Governance:** The Admin receives a WhatsApp message and replies "YES".
4.  **Verification:** The Node.js gateway hits the Python webhook. `app.py` verifies the Admin's phone number.
5.  **Execution:** The system triggers `twitter_skill.py` to publish the tweet, logs the success, and moves the file to `Done/`.

---

## 4. Key Design Patterns
*   **Security First:** No API keys in code (`.env` only). Strict programmatic barriers prevent unapproved public data mutations.
*   **Model Context Protocol (MCP):** Structured, schema-driven communication between the AI reasoning layer and external services (like Odoo).
*   **Idempotency:** State is managed via file paths (e.g., a file cannot be in `Needs_Action` and `Done` simultaneously), preventing double-execution of tasks.
