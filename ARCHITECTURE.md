# K-Electric AI Employee Architecture (Gold Tier)

## 1. System Overview
The K-Electric AI Employee is an autonomous agent system built to manage business operations, including accounting, social media, and customer support. It follows a "Local-First, Human-in-the-Loop" philosophy.

## 2. Core Components

### A. The Brain (Gemini Code + Orchestrator)
- **Gemini Code**: The primary reasoning engine used for high-level decision making and planning.
- **Orchestrator (`KE_AI_Vault/scripts/gemini_orchestrator.py`)**: A Python-based master process that manages the task lifecycle (Perception -> Reasoning -> Action). It uses `watchdog` to monitor the vault for new tasks.

### B. The GUI & Memory (Obsidian Vault)
- **Obsidian**: Acts as the dashboard and long-term memory.
- **Dashboard (`Dashboard.md`)**: Real-time overview of KPIs, revenue, and system status.
- **Needs_Action/**: Folder where watchers drop new tasks.
- **Plans/**: Folder where the AI stores its multi-step execution plans.
- **Pending_Approval/**: Safety buffer for sensitive actions (payments, social posts).
- **Done/**: Archive for completed tasks.

### C. The Senses (Watchers)
- **Gmail/WhatsApp/Social Watchers**: Lightweight Python scripts that monitor external channels and drop `.md` task files into `Needs_Action`.
- **Odoo Sync Watcher**: Monitors the Odoo ERP for updates and logs them in the vault.

### D. The Hands (MCP Servers)
- **Odoo MCP Server (`odoo_mcp_server.py`)**: Connects to Odoo Community via XML-RPC for accounting and CRM actions.
- **Social MCP Server (`social_mcp_server.py`)**: Connects to Facebook, Instagram, and Twitter (X). Recently updated to support real Twitter API v2 integration via Bearer Tokens.
- **Filesystem MCP**: Manages vault file movements and archival.

## 3. Workflow Example (Approval Loop)
1. **Perception**: Banking Watcher detects a transaction and injects context from `Accounting/Rates.md`.
2. **Task Creation**: AI determines an approval is needed for a sensitive transaction.
3. **Approval**: User moves the request file from `Pending_Approval` to `Approved`.
4. **Action**: The Orchestrator (`ApprovedHandler`) detects the file in `Approved`, executes the linked MCP action, and logs the success.
5. **Archival**: Files are moved to `/Done` automatically.

## 4. Lessons Learned & Best Practices
- **Safety First**: Always use a `Pending_Approval` folder for external actions to prevent "rogue agent" behavior.
- **Data Integrity**: Maintaining a strict folder structure (/Needs_Action -> /In_Progress -> /Done) prevents double-processing.
- **Context Efficiency**: Keep the Dashboard and Handbook concise so the AI can process them quickly without exceeding token limits.
- **Mock vs. Real**: Start with mock watchers for development, but build real MCP servers (like the Odoo/Social ones implemented here) for production value.

## 5. Security Disclosure
- Secrets (API keys, passwords) are stored in `.env` files which are excluded from source control.
- Vault data is local-first, ensuring data privacy.
- External actions require human approval if they exceed specified thresholds.
